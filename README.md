# ميزان — نظام محاسبي عربي

نظام محاسبة ومشتريات ومبيعات بواجهة عربية كاملة (RTL)، مبني على **القيد المزدوج** الحقيقي:
كل فاتورة وكل سند يولّد قيداً متوازناً في دفتر الأستاذ، ولا توجد أي أرصدة محسوبة خارج الدفتر.

مستوحى من فلسفة **Manager (manager.io)**: بساطة في الاستخدام، صرامة في المحاسبة.

---

## ما الذي يعمل الآن

| المجال | التفاصيل |
|---|---|
| **شجرة الحسابات** | 45 حساباً عربياً جاهزاً، 5 أنواع، حسابات تجميعية وفرعية، حسابات نظامية محميّة |
| **دفتر الأستاذ** | قيود مزدوجة متوازنة إجبارياً، ترقيم تسلسلي، قيود يدوية، إقفال الفترات |
| **العملاء والموردون** | أرصدة محسوبة من حسابي الذمم مباشرة، كشف حساب لكل طرف |
| **فواتير المبيعات والمشتريات** | مسودة ← ترحيل ← إلغاء، ضريبة قيمة مضافة لكل سطر، ترقيم سنوي تلقائي |
| **سندات القبض والصرف** | توزيع السند على عدة فواتير مع التحقق من المتبقي |
| **الأصناف والخدمات** | بطاقة صنف بحساباتها، أسعار استرشادية، حد إعادة طلب، صنف مخزني أو خدمة |
| **المخزون** | تقييم بالمتوسط المرجّح المتحرك، تكلفة بضاعة مباعة آلية، كشف حركة لكل صنف |
| **تسويات المخزون** | أرصدة افتتاحية وفروق جرد وتالف مقابل الحساب الذي تختاره |
| **التقارير** | ميزان المراجعة، قائمة الدخل، المركز المالي، كشف حساب، أعمار الديون، أرصدة المخزون، لوحة مؤشرات |
| **الصلاحيات** | مالك / محاسب / مُطّلع، مع JWT وتحديد معدّل محاولات الدخول |

### دقّة الأرقام

كل المبالغ تُخزَّن وتُحسب كـ **أعداد صحيحة بالوحدة الصغرى** (`BigInt`) مع تقريب نصف لأعلى،
على الخادم وفي المتصفح بنفس المنطق تماماً. لا توجد أرقام عشرية عائمة في أي مكان،
فلا تظهر فروق القرش التي تصيب الأنظمة التي تستخدم `float`.

- المبالغ: منزلتان عشريتان
- الكميات: ثلاث منازل
- نسب الضريبة: عُشر من المئة (15% تُخزَّن 1500)

### تقييم المخزون

التقييم بـ **المتوسط المرجّح المتحرك**: مع كل وارد يُعاد حساب متوسط تكلفة الوحدة،
وكل منصرف يخرج بالمتوسط الجاري لحظتَه، وتُثبَّت تكلفته في القيد المحاسبي.

لأن المتوسط يعتمد على ترتيب الحركات، يفرض النظام قاعدتين تحفظان تطابق الدفتر مع الواقع:

1. **لا ترحيل بتاريخ أسبق** من آخر حركة مخزون للصنف.
2. **لا إلغاء ترحيل لمستند تلته حركات أخرى** على الصنف نفسه — ألغِ الأحدث أولاً.

كما يُمنع البيع بأكثر من الرصيد المتاح (لا أرصدة سالبة).

## التشغيل

### المتطلبات
Node.js 20 أو أحدث.

### الخادم (backend)

```bash
cd backend
npm install
cp .env.example .env          # ثم عدّل JWT_SECRET
npx prisma db push
npm run seed                  # شجرة الحسابات + مستخدم المالك
npm run dev                   # http://localhost:4000
```

بيانات الدخول الافتراضية بعد `seed`:

```
admin@mizan.local / Mizan@12345
```

غيّرها فوراً قبل أي استخدام حقيقي (عبر `SEED_EMAIL` و `SEED_PASSWORD` في `.env`).

### الواجهة (frontend)

```bash
cd frontend
npm install
npm run dev                   # http://localhost:5173
```

الواجهة توجّه `/api` تلقائياً إلى الخادم على المنفذ 4000.

### الاختبارات

```bash
cd backend && npm test
```

تغطي: دقّة الحسابات، توازن القيود، منع القيد على الحسابات التجميعية، إقفال الفترات،
دورة فاتورة ← سند كاملة، توازن ميزان المراجعة والمركز المالي، أعمار الديون، والصلاحيات.

### الحسابات النظامية

خمسة حسابات يعتمد عليها الترحيل ولا يمكن حذفها أو تغيير نوعها:

| المفتاح | الحساب | يُستخدم في |
|---|---|---|
| `RECEIVABLE` | 1201 ذمم العملاء | طرف مدين في فواتير المبيعات، دائن في سندات القبض |
| `PAYABLE` | 2101 ذمم الموردين | طرف دائن في فواتير المشتريات، مدين في سندات الصرف |
| `TAX_OUTPUT` | 2102 ضريبة مخرجات | ضريبة فواتير المبيعات |
| `TAX_INPUT` | 1202 ضريبة مدخلات | ضريبة فواتير المشتريات |
| `RETAINED` | 3201 الأرباح المحتجزة | الإقفال السنوي (مرحلة لاحقة) |
| `INVENTORY` | 1301 مخزون البضاعة | إدخال وإخراج البضاعة |
| `COGS` | 5101 تكلفة البضاعة المباعة | تكلفة المبيعات عند الترحيل |
| `STOCK_ADJUST` | 5102 فروق وتسويات المخزون | الطرف المقابل المقترح لفروق الجرد |

### القيود المولَّدة

**فاتورة مبيعات** — من ذمم العملاء / إلى الإيرادات + ضريبة المخرجات
**فاتورة مشتريات** — من المصروفات + ضريبة المدخلات / إلى ذمم الموردين
**سند قبض** — من النقدية / إلى ذمم العملاء
**سند صرف** — من ذمم الموردين / إلى النقدية

عندما يحوي السطر صنفاً مخزنياً:

- **الشراء** يُقيَّد على حساب المخزون بدل المصروف، وتدخل الكمية بتكلفتها.
- **البيع** يضيف إلى القيد نفسه: من تكلفة البضاعة المباعة / إلى المخزون، بالمتوسط المرجّح.
- **التسوية** تقيّد صافي الفرق بين المخزون والحساب المقابل الذي تختاره
  (رأس المال للأرصدة الافتتاحية، فروق المخزون للجرد والتالف).

إلغاء الترحيل يحذف القيد بالكامل، ويُمنع إن كانت الفاتورة مرتبطة بسندات.

## ما لم يُبنَ بعد

لم يُبنَ بعد:

- **الأصول الثابتة** والإهلاك الآلي
- **المستودعات المتعددة** (المخزون حالياً مستودع واحد)
- **طرق تقييم أخرى** (FIFO / LIFO) — المتاح هو المتوسط المرجّح
- **تعدّد العملات**
- **الإقفال السنوي** الآلي إلى الأرباح المحتجزة
- **تصدير** التقارير إلى PDF/Excel (الطباعة من المتصفح متاحة)
- **إدارة المستخدمين** من الواجهة (تُضاف حالياً من قاعدة البيانات أو السكربت)

## ملاحظات نشر

- قاعدة البيانات الافتراضية SQLite في ملف واحد — انسخه احتياطياً بانتظام.
  للتحويل إلى PostgreSQL: غيّر `provider` في `schema.prisma` و `DATABASE_URL` فقط.
- `JWT_SECRET` **يجب** تغييره في الإنتاج.
- الواجهة لا تطلب أي مورد خارجي (لا خطوط ولا سكربتات من الإنترنت)، فتعمل على شبكة محلية مغلقة.
