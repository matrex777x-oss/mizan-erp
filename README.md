# ميزان — نظام محاسبي عربي

نظام محاسبة ومشتريات ومبيعات بواجهة عربية كاملة (RTL)، مبني على **القيد المزدوج** الحقيقي:
كل فاتورة وكل سند يولّد قيداً متوازناً في دفتر الأستاذ، ولا توجد أي أرصدة محسوبة خارج الدفتر.

مستوحى من فلسفة **Manager (manager.io)**: بساطة في الاستخدام، صرامة في المحاسبة.

---

## ما الذي يعمل الآن

| المجال | التفاصيل |
|---|---|
| **شجرة الحسابات** | 45 حساباً عربياً جاهزاً، 5 أنواع، حسابات تجميعية وفرعية، حسابات نظامية محميّة |
| **دفتر الأستاذ** | قيود مزدوجة متوازنة إجبارياً، ترقيم تسلسلي، قيود يدوية، إقفال الفترات |
| **العملاء والموردون** | أرصدة محسوبة من حسابي الذمم مباشرة، كشف حساب لكل طرف |
| **فواتير المبيعات والمشتريات** | مسودة ← ترحيل ← إلغاء، ضريبة قيمة مضافة لكل سطر، ترقيم سنوي تلقائي |
| **سندات القبض والصرف** | توزيع السند على عدة فواتير مع التحقق من المتبقي |
| **الأصناف والخدمات** | بطاقة صنف بحساباتها، أسعار استرشادية، حد إعادة طلب، صنف مخزني أو خدمة |
| **المخزون** | تقييم بالمتوسط المرجّح المتحرك، تكلفة بضاعة مباعة آلية، كشف حركة لكل صنف |
| **تسويات المخزون** | أرصدة افتتاحية وفروق جرد وتالف مقابل الحساب الذي تختاره |
| **التقارير** | ميزان المراجعة، قائمة الدخل، المركز المالي، كشف حساب، أعمار الديون، أرصدة المخزون، لوحة مؤشرات |
| **الصلاحيات** | خمسة أدوار لكل منشأة على حدة بخريطة قدرات واحدة، مع JWT وتحديد معدّل محاولات الدخول |
| **تعدّد المنشآت** | قاعدة بيانات مستقلة لكل منشأة ومبدّل بينها — لا تلتقي حساباتها |
| **إدارة المستخدمين** | إنشاء وتعطيل وإعادة تعيين كلمة المرور ومنح الوصول لكل منشأة |
| **الأصول الثابتة** | بطاقة أصل، إهلاك شهري بالقسط الثابت أو المتناقص، استبعاد بربح أو خسارة |
| **الإقفال السنوي** | قيد إقفال يرحّل نتيجة السنة إلى الأرباح المحتجزة، بسنة مالية تتبع إعداداتك |
| **سجل التدقيق** | من دخل، ومن غيّر صلاحية، ومن أعاد تعيين كلمة مرور — ومتى |
| **التصدير** | تنزيل أي تقرير إلى Excel (xlsx) أو PDF عربي بترويسة المنشأة |
| **لوحة الآدمن** | بيانات المنشأة، ترقيم المستندات، تعطيل الوحدات، حالة النظام ونسخه الاحتياطية |

### دقّة الأرقام

كل المبالغ تُخزَّن وتُحسب كـ **أعداد صحيحة بالوحدة الصغرى** (`BigInt`) مع تقريب نصف لأعلى،
على الخادم وفي المتصفح بنفس المنطق تماماً. لا توجد أرقام عشرية عائمة في أي مكان،
فلا تظهر فروق القرش التي تصيب الأنظمة التي تستخدم `float`.

- المبالغ: منزلتان عشريتان
- الكميات: ثلاث منازل
- نسب الضريبة: عُشر من المئة (15% تُخزَّن 1500)

### تقييم المخزون

التقييم بـ **المتوسط المرجّح المتحرك**: مع كل وارد يُعاد حساب متوسط تكلفة الوحدة،
وكل منصرف يخرج بالمتوسط الجاري لحظتَه، وتُثبَّت تكلفته في القيد المحاسبي.

لأن المتوسط يعتمد على ترتيب الحركات، يفرض النظام قاعدتين تحفظان تطابق الدفتر مع الواقع:

1. **لا ترحيل بتاريخ أسبق** من آخر حركة مخزون للصنف.
2. **لا إلغاء ترحيل لمستند تلته حركات أخرى** على الصنف نفسه — ألغِ الأحدث أولاً.

كما يُمنع البيع بأكثر من الرصيد المتاح (لا أرصدة سالبة).

## التشغيل بأمر واحد (منفذ واحد)

للاستخدام داخل **تطبيق نفق** أو أي مشغّل خارجي (خدمة نظام، حاوية، منصة استضافة):
الخادم يقدّم الواجهة المبنيّة بنفسه، فالتطبيق كله يعمل على **منفذ واحد**.

يدعم المشروع **كل أنماط التشغيل الشائعة** في هذه المشغّلات — أيّها استخدم المشغّل يعمل:

| النمط | ما يحدث |
|---|---|
| `npm install` ثم `npm start` | `postinstall` يثبّت الطرفين ويبني الواجهة، ثم يقلع |
| `node index.js` أو `node .` | يثبّت الواجهة ويبنيها عند الحاجة ثم يقلع |
| `./start.sh` / `start.bat` | يثبّت ويبني عند الحاجة ثم يقلع |
| `npm run setup` ثم `npm start` | الطريقة الصريحة |

```bash
PORT=8080 npm start           # أو ./start.sh
set PORT=8080 && start.bat    # ويندوز
```

أول تشغيل يتكفّل بكل شيء تلقائياً:

1. يثبّت الحزم ويبني الواجهة
2. ينشئ `backend/.env` بمفتاح توقيع **عشوائي** (لا يُولَّد مرتين)
3. ينشئ قاعدة النظام، وأول منشأة بقاعدتها وشجرة حساباتها، وأول آدمن
4. يطبع بيانات الدخول في السجل ثم يقلع

التشغيلات التالية تقلع مباشرة دون إعادة بناء.

### متغيرات البيئة

| المتغير | الافتراضي | الغرض |
|---|---|---|
| `PORT` | `4000` | المنفذ الذي يستمع عليه التطبيق |
| `HOST` | `0.0.0.0` | عنوان الاستماع |
| `DATA_DIR` | `backend/prisma` | مجلد البيانات: `system.db` و `businesses/<slug>.db` لكل منشأة |
| `JWT_SECRET` | يُولَّد عشوائياً | مفتاح توقيع الجلسات |
| `SEED_EMAIL` | `admin@mizan.local` | بريد أول آدمن |
| `SEED_PASSWORD` | تُولَّد عشوائياً | كلمة مرور أول آدمن — ويُطلب تغييرها عند أول دخول |

**مهم:** استخدم `DATA_DIR` في التشغيل الحقيقي (مثل `DATA_DIR=/var/lib/mizan`)
وإلا فقد تُفقد البيانات عند إعادة نشر الكود.

### تعدّد المنشآت

لكل منشأة **ملف قاعدة بيانات مستقل** في `DATA_DIR/businesses/`، وقاعدة نظام
مركزية واحدة فيها المستخدمون والمنشآت والصلاحيات وسجل التدقيق لا غير.
فلا يمكن لاستعلام في منشأة أن يرى بيانات منشأة أخرى، وتُنسخ كل منشأة وتُنقل وحدها.

ينشئ آدمن النظام المنشآت من «إدارة النظام ← المنشآت»، ويمنح كل مستخدم دوره في كل
منشأة على حدة؛ فقد يكون مالكاً في واحدة ومحاسباً في أخرى. ومن يصل إلى أكثر من
منشأة يبدّل بينها من أعلى الشريط الجانبي.

### الأدوار

لكل مستخدم دور في كل منشأة على حدة، وقدرات الدور معرَّفة في خريطة واحدة
(`backend/src/lib/capabilities.js`) يفرضها الخادم وتبني منها الواجهة شاشة
«الأدوار والصلاحيات» — فما تراه في الشاشة هو ما يفرضه الخادم حرفياً.

| الدور | ما يستطيعه |
|---|---|
| **مالك** | كل شيء، ومنه إعدادات المنشأة وإقفال الفترات |
| **محاسب** | الدفتر كله: الفواتير والسندات والقيود والتقارير — عدا إعدادات المنشأة |
| **مبيعات** | فواتير المبيعات وسندات القبض والعملاء، مع عرض الأصناف وأرصدتها |
| **مخزن** | الأصناف وتسويات المخزون وتقاريره، مع عرض فواتير الشراء |
| **مُطّلع** | عرض كل شيء دون أي تعديل |

الترحيل إلى دفتر الأستاذ قدرة منفصلة عن الكتابة، فيمكن لاحقاً السماح بإنشاء
مسودة دون إثبات قيد. وما لا يملكه الدور يختفي من الشريط الجانبي ومن لوحة
المؤشرات بدل أن يُعرض ثم يُرفض.

### ترقيم المستندات

بادئة كل نوع وعدد الخانات ودخول السنة تُضبط من «إعدادات المنشأة»:
`INV-2026-0001` أو `MBT-000001`. تغيير البادئة يبدأ تسلسلاً جديداً من 1 ولا
يمسّ أرقام المستندات المحفوظة، ولا يصح تكرار البادئة بين نوعين.

### الوحدات

وحدة المخزون تُعطَّل للمنشأة الخدمية، فتختفي شاشاتها وتُرفض الأصناف المخزنية
وتسوياتها. لا يمكن تعطيلها بعد تسجيل أي حركة مخزون.

### تصدير التقارير

كل تقرير فيه زرّا **Excel** و**PDF**. ملف Excel جدول حقيقي بأعمدة رقمية تُجمع
وتُصفّى، وPDF صفحة عربية بترويسة المنشأة ورقمها الضريبي.

PDF يُولَّد بمتصفّح Chrome أو Edge **المثبَّت على الجهاز** (لا يُنزَّل Chromium مع
المشروع)، لأنه وحده يعرض العربية بتشكيلها الصحيح. اضبط `CHROME_PATH` إن كان
متصفّحك في مسار غير معتاد؛ وإن لم يوجد متصفّح يختفي زر PDF ويبقى Excel والطباعة.

### النسخ الاحتياطية

من «إدارة النظام ← النظام» تُنزَّل نسخة من قاعدة أي منشأة: ملف SQLite كامل يعمل
وحده، يُؤخذ من لقطة متّسقة (`VACUUM INTO`) دون إيقاف الخادم. وتعرض الشاشة نسخة
التطبيق ومجلد البيانات وأحجام القواعد وعدد المستخدمين وأحداث التدقيق.

### كلمات المرور

تُخزَّن بـ bcrypt، وهي تجزئة في اتجاه واحد: **لا يستطيع أحد — ولا آدمن النظام —
عرض كلمة مرور قائمة**. المتاح:

- **إظهار ما تكتبه الآن** في أي حقل كلمة مرور (زر «إظهار»).
- **إعادة التعيين** بيد الآدمن: كلمة مؤقتة تُعرض مرة واحدة، ويُلزَم صاحبها بوضع
  كلمة يعرفها وحده عند أول دخول.
- **سكربت طوارئ** على الجهاز حين ينسى آدمن النظام الوحيد كلمته:

```bash
cd backend
npm run reset-password -- --list
npm run reset-password -- admin@mizan.local
```

### الترقية من نسخة ما قبل تعدّد المنشآت

أول إقلاع يجد `backend/prisma/dev.db` يرحّلها تلقائياً بعد أخذ نسخة احتياطية:
المستخدمون إلى قاعدة النظام، والبيانات المحاسبية إلى منشأة أولى اسمها «منشأتي».
القاعدة القديمة لا تُحذف بل تُعاد تسميتها `dev.db.migrated-<الوقت>`.
يدوياً: `cd backend && npm run migrate:legacy`.

## التشغيل للتطوير

### المتطلبات
Node.js 20 أو أحدث.

### الخادم (backend)

```bash
cd backend
npm install                   # يولّد عميلَي Prisma: المنشأة والنظام
npm run dev                   # http://localhost:4000
```

أول إقلاع يتكفّل بالباقي: ينشئ قاعدة النظام وأول منشأة بشجرة حساباتها وأول آدمن،
ويطبع بيانات دخوله في السجل. تُضبط بـ `SEED_EMAIL` و `SEED_PASSWORD` في `.env`،
ويُطلب تغيير كلمة المرور عند أول دخول على كل حال.

لبذر شجرة الحسابات في قاعدة منشأة بعينها: `node prisma/seed.js <slug>`.

### الواجهة (frontend)

```bash
cd frontend
npm install
npm run dev                   # http://localhost:5173
```

الواجهة توجّه `/api` تلقائياً إلى الخادم على المنفذ 4000.

### الاختبارات

```bash
cd backend && npm test
```

تغطي: دقّة الحسابات، توازن القيود، منع القيد على الحسابات التجميعية، إقفال الفترات،
دورة فاتورة ← سند كاملة، توازن ميزان المراجعة والمركز المالي، أعمار الديون، والصلاحيات.
ويغطي `roles.test.js` **حدود كل دور**: ما يصل إليه وما يُرفض له، وتماسك خريطة
القدرات نفسها، ومطابقة ما يعرضه `/api/auth/roles` لما يفرضه الخادم.
ويغطي `businesses.test.js` **عزل المنشآت**: ألّا ترى منشأة بيانات أخرى، وألّا يصل
مستخدم إلى منشأة بلا عضوية، وإلزام تغيير كلمة المرور، وإعادة تعيينها، وسجل التدقيق.

### الحسابات النظامية

خمسة حسابات يعتمد عليها الترحيل ولا يمكن حذفها أو تغيير نوعها:

| المفتاح | الحساب | يُستخدم في |
|---|---|---|
| `RECEIVABLE` | 1201 ذمم العملاء | طرف مدين في فواتير المبيعات، دائن في سندات القبض |
| `PAYABLE` | 2101 ذمم الموردين | طرف دائن في فواتير المشتريات، مدين في سندات الصرف |
| `TAX_OUTPUT` | 2102 ضريبة مخرجات | ضريبة فواتير المبيعات |
| `TAX_INPUT` | 1202 ضريبة مدخلات | ضريبة فواتير المشتريات |
| `RETAINED` | 3201 الأرباح المحتجزة | الإقفال السنوي (مرحلة لاحقة) |
| `INVENTORY` | 1301 مخزون البضاعة | إدخال وإخراج البضاعة |
| `COGS` | 5101 تكلفة البضاعة المباعة | تكلفة المبيعات عند الترحيل |
| `STOCK_ADJUST` | 5102 فروق وتسويات المخزون | الطرف المقابل المقترح لفروق الجرد |

### القيود المولَّدة

**فاتورة مبيعات** — من ذمم العملاء / إلى الإيرادات + ضريبة المخرجات
**فاتورة مشتريات** — من المصروفات + ضريبة المدخلات / إلى ذمم الموردين
**سند قبض** — من النقدية / إلى ذمم العملاء
**سند صرف** — من ذمم الموردين / إلى النقدية

عندما يحوي السطر صنفاً مخزنياً:

- **الشراء** يُقيَّد على حساب المخزون بدل المصروف، وتدخل الكمية بتكلفتها.
- **البيع** يضيف إلى القيد نفسه: من تكلفة البضاعة المباعة / إلى المخزون، بالمتوسط المرجّح.
- **التسوية** تقيّد صافي الفرق بين المخزون والحساب المقابل الذي تختاره
  (رأس المال للأرصدة الافتتاحية، فروق المخزون للجرد والتالف).

إلغاء الترحيل يحذف القيد بالكامل، ويُمنع إن كانت الفاتورة مرتبطة بسندات.

## ما لم يُبنَ بعد

لم يُبنَ بعد:

- **الأصول الثابتة** والإهلاك الآلي
- **المستودعات المتعددة** (المخزون حالياً مستودع واحد)
- **طرق تقييم أخرى** (FIFO / LIFO) — المتاح هو المتوسط المرجّح
- **تعدّد العملات**
- **الإقفال السنوي** الآلي إلى الأرباح المحتجزة
- **تصدير** التقارير إلى PDF/Excel (الطباعة من المتصفح متاحة)
- **إدارة المستخدمين** من الواجهة (تُضاف حالياً من قاعدة البيانات أو السكربت)

## ملاحظات نشر

- قاعدة البيانات الافتراضية SQLite في ملف واحد — انسخه احتياطياً بانتظام
  (`DATA_DIR/mizan.db` أو `backend/prisma/dev.db`).
  للتحويل إلى PostgreSQL: غيّر `provider` في `schema.prisma` و `DATABASE_URL` فقط.
- `JWT_SECRET` **يجب** تغييره في الإنتاج.
- الواجهة لا تطلب أي مورد خارجي (لا خطوط ولا سكربتات من الإنترنت)، فتعمل على شبكة محلية مغلقة.
